GPT 黑话、口癖、文风及语言边界的讨论

GPT 的文风不能只用“黑话”概括。有些看似别扭的词其实是专业术语，比如夹具（fixture）、落盘、wiring、preset、framing等；有些句式本身不必然错，比如“先说结论”（秘书式地发言），“不是……而是……”（理清概念），“稳稳地接住”情绪托底，问题在于高频模板化，太容易出现了，AI的问题不是单个问题回答得好不好，而是倾向于相同的句式，固定的表达，即一眼AI。本文讨论三件事：专业术语如何区别于伪专业感，不自然的来源很多在于机翻和直译，以及 post-training 中的 credit assignment 误分配如何把本该奖励的能力、简洁和温暖，连同共现的表层口癖一起奖励。诚然，agentic 时代，行胜于言，execution 大于 talking；稳稳地解决问题，比说一两句“稳稳地接住你”重要。最后，那些或者为机翻、或者为通感、或者在化用，是否就像成语，比如“朝三暮四”/“张冠李戴”，一直我很喜欢的《笑傲江湖》的书名的来源，早已脱离了它字面本来应有之义，是否在赋予一些文字新的内涵，拓展表达的边界。

本文主张把 GPT 的黑话、口癖和文风一分为三：第一类是有工程语境的专业用词；第二类是读得懂但不自然的翻译腔；第三类是 post-training 放大的模板化口癖。三者混在一起骂，最后只会变成廉价判断：凡是不喜欢的词，都叫 AI 味。

一、专业用词不是黑话，滥用专业感才是

专业术语需要从“黑话”里先捞出来。真正的术语有三个特征：压缩稳定概念，减少协作歧义，指向具体动作或判断。满足这三点的词，不该因为不像日常中文而被反对。

  1. 落盘：把状态、缓存、日志或结果持久化到磁盘，而不是只留在内存里；它区分了“临时存在”和“可恢复、可审计、可复现”的工程状态
  2. fixture / 夹具 测试运行前准备好的可重复上下文、依赖、数据或资源 pytest 文档里 fixture 本来就强调为测试提供可靠、可重复的上下文[1]
  3. wiring / 接线 把模块、依赖、配置、事件流或 handler 连接起来；它不是“写代码”的同义词，而是指组件之间的装配关系
  4. preset / 预设 预先配置好的一组参数、样式、位置或策略；英文 preset 本来就有预先设置、预先选择好的设置项之义[2]
  5. framing 对问题边界、目标函数、评价口径和叙事角度的框定；很多争论的差异不在事实，而在问题被如何 frame

这些词的问题不在“洋气”，而在它们真的有区分度。把 fixture 全部改成“测试数据”会丢失含义，因为 fixture 可能是数据库连接、临时目录、mock server、依赖注入容器，或者一整套测试前置状态。把 wiring 全部改成“连接”也会变钝，因为 wiring 关心组件之间的依赖关系、调用路径和生命周期。

真正的问题在另一边：模型会把“术语”扩展成“专业感表演”。

比如它会把普通的保存说成“落盘”，把普通的继续处理说成“收口”，把普通的确认说成“钉死”，把普通的备用方案说成“兜底”，把普通的总结说成“闭环”。这些词单独都未必错，但一旦脱离具体上下文，就会从工程语言滑向办公室语言。它不再压缩信息，只是在给回答镀一层职业感。

判断标准很简单：删掉后技术区分会消失，就是术语；删掉后意思不变，只是少了一点“显得专业”的气味，就是修辞噪音。

二、很多口癖首先是机翻腔：不一定难懂，但很伤 writing

并不是所有 GPT 口癖都会严重影响阅读。很多表达只是第一次读起来别扭，熟悉以后很快能懂。比如“更干净的验证”“claim 更硬”“context 不崩”“把根因钉死”，技术圈读者通常能迅速反推英文骨架：cleaner validation、stronger claim、context does not break、nail down the root cause。

问题是，这种可理解性依赖读者补完。它不是自然中文在直接工作，而是英文隐喻、英文动词搭配、英文产品文案节奏穿了一件中文外衣。

鸭哥在《写作中的 AI 味是哪儿来的》里把这个问题说得很直接：AI 中文的味道，很大程度上就是翻译腔；它的核心特征，是“骨架为英文的中文句子”。文中列出四类高频套路：用物理动作描述思考过程，用形容词替读者先下判断，用抽象名词做主语并用形容词收尾，以及有中文译法的英文词直接混入句子。[3]

translationese 也不是一个玄学感受。PLOS One 2026 年那篇关于 LLM machine translationese 的论文，用 dependency triplets、16 个分类器和 SHAP 去区分人类翻译与 LLM 翻译；其中 SVM 的平均 F1 达到 0.93，说明机器翻译腔可以通过句法特征被稳定检测出来[4]。这件事给了一个很重要的旁证：读者感觉“这句中文像翻译过来的”，并不只是审美洁癖，它背后有可统计的句法模式。

按鸭哥的 taxonomy，主干问题大致可以分成四类：

  1. 物理动作写思考：“接住”、击穿、打穿、锋利、不崩、不爆 把理解、论证、状态变化说成物理动作
  2. 形容词抢跑：更锋利、更干净、逻辑很清晰、问题很直接 先替读者下判断，再用冒号引出内容
  3. 抽象名词主语 “工程上的现实更难看”一类句子 主语过虚，结论靠形容词兜住，事实没有展开
  4. 英文词直留 context、state、cache、claim 混在中文里（但部分很难找到最佳中文对照时，我其实非常倾向于中英混杂的方式，至少没有丢失信息量）；读者需要在中英文之间来回切换

这四类抓住了翻译腔的主干，但放到 GPT/Codex 这类技术协作语境里，还需要补几类遗漏。

第一类遗漏，是介词和动词搭配的直译。比如“桥成一个服务”，很可能来自 bridge into a service 或 bridge A into B。问题不只是“桥成”这个词新，而是 bridge 的工程隐喻和 into 的转化结构一起被搬进中文。中文更自然的落点，通常是“封装成服务”“接成一个服务层”“抽成服务”“作为服务暴露出去”，具体取决于它到底是在说封装、适配、转发，还是服务化。

第二类遗漏，是度量隐喻的硬搬。比如“视觉记忆通常很胖”，背后大概率是 heavy：memory-heavy、heavy visual memory、heavy cache。中文里“胖”当然可以作为比喻，但如果上下文没有支撑，它表达的其实不是胖，而是“占显存”“占内存”“体积大”“保留成本高”“状态很重”。这类句子最危险的地方在于它好像很有画面感，但读者不确定它在说容量、延迟、拷贝成本、序列长度，还是检索负担。

第三类遗漏，是 low-verbosity 造成的关系压缩。比如“只要这三块不一起收，into、Inspector、懒加载 inspect section 这类问题还会反复漏出来”。这句话并不难懂，但“收”和“漏”把太多关系压没了。“收”到底是统一纳入同一条检查链路、合并到同一层抽象、一起修，还是统一测试？“漏出来”到底是被遗漏、逃过检查、进入未覆盖路径，还是线上再次暴露？更自然的写法应该把动词补全：只要不把这三块统一纳入同一套检查和修复路径，into、Inspector、懒加载 inspect section 这类问题就会反复被遗漏，或者继续出现在未覆盖的分支里。

因此，GPT 中文常见的别扭感，可以再整理成一张更贴近技术写作的表：

  1. 我都接住 I caught all of them 收到了 / 记下了 / 采纳了；把理解、接收、回应误压成物理动作
  2. 更锋利的重构 a sharper refactoring 更准确 / 更有力 / 更少废话的改写 sharp；在英文里自然，中文里容易变成悬浮形容词
  3. 验证得更干净 cleaner validation 证得更清楚 / 副作用更少 / 检查范围更明确；clean 的技术语感被直搬过来
  4. context 不崩 context does not break 上下文不乱 / 状态不失控；英文 break 的隐喻被保留
  5. 把根因钉死 nail down the cause 查清根因 / 确认根因 nail down 的“确定”义被物理化成“钉死”[5]
  6. 桥成一个服务 bridge into a service 封装成服务 / 接成服务层 / 抽成服务 ；bridge 和 into 的搭配被硬搬进中文
  7. 视觉记忆通常很胖 visual memory is heavy 占显存大 / 状态很重 / 保留成本高；heavy 被译成胖，但维度没有说明
  8. 这三块不一起收，问题会漏出来 collect/close them together; issues leak out 不统一纳入检查链路，就会反复遗漏；低 verbosity 把操作、对象、失败机制都压没了

这类表达往往不是错句，所以很难用校对规则直接拦掉。它们只是让中文变硬、变扁，像一段英文的影子。

在 agent 协作和技术问答里，理解效率常常比文体美感更重要。模型把 bug 定位清楚、patch 写对、测试跑通，即使中间夹两句“把问题收口”，工具价值也不会消失。但 writing 不是同一件事。好的写作不该要求读者在脑子里常驻一台翻译机。技术协作可以容忍“能懂就行”，写作不能长期依赖“反正能猜出来”。

因此，对翻译腔更准确的判断是：它对 reading 的伤害常常被夸大，对 writing 的伤害常常被低估。

三、post-training 真正放大的，是“高分能力”的表层伴随物

第三层是 post-training。这里才是 GPT 口癖最核心的机制。

现代 assistant 不是只靠预训练语料自然长出来的。它还要经过指令微调、偏好优化、强化学习、产品侧风格控制、系统提示和各种 eval（评测）。它被同时推向很多目标：helpful（有帮助）、safe（安全）、concise（简洁）、warm（温暖）、professional（职业）、agentic（能主动推进任务）、controllable（可控）、scannable（便于扫读）。

这些目标单独看都合理。OpenAI 的 release notes（发布日志）写过，GPT-5 默认 personality 后来被调得更 warm / familiar，因为早期版本被用户反馈为太 reserved / professional（克制、职业化）[6]。Model Spec也把 warm、clear、direct、professional、concise写进行为要求，同时提醒不要滑向 saccharine（甜腻）或 therapy speak（心理咨询腔）[7]。ChatGPT personality 文档里，Efficient（高效型）被定义为 concise and plain（简洁、朴素），Professional（职业型）强调 formal and structured（正式、结构化），Friendly（友好型）更 conversational（像对话）[8]。GPT-5 prompting guide（提示指南）还引入 verbosity（详略度）参数，用来影响最终回答长度，并强调 GPT-5 对 verbosity、tone（语气）、tool calling behavior（工具调用行为）的提示很敏感[9]。

把这些目标合在一起，模型得到的不是一个纯粹的“好中文”目标，而是一个多目标优化后的产品人格：

它要显得可靠，所以倾向于强判断；要显得清楚，所以倾向于固定结构；要显得温暖，所以倾向于轻安抚；要节省 token，所以倾向于短句和模板；要适合 agentic workflow，所以倾向于状态汇报、动作分解和进度同步；要减少用户流失，所以倾向于结尾留一个可继续对话的口子。

Model Spec 对 follow-up question 的态度其实很能说明这种张力：互动场景里可以问用户是否问题解决、是否需要更多细节；但面对清晰、离散的问题，又通常应该直接回答，不要加无用 follow-up[10]。也就是说，规范层面知道“保持对话开放”和“别多嘴”之间有边界。但训练和产品默认值一旦规模化，这个边界很容易被某些高频句式磨平。

这就是口癖产生的土壤。

“先说结论”是一种 scannability 模板。它让回答显得清楚、节省读者定位成本，也节省模型组织段落的成本。

“不是 X，而是 Y”是一种 contrast 模板。它用一个否定对象制造洞见感，再用一个肯定对象完成转折。问题是很多时候 X 根本不是读者的真实误解，模型只是先立一个稻草人，再显得自己很会拨乱反正。

“最稳”“最小改动”“最值得”是一种 token-efficient 的判断压缩。它把比较对象、风险模型、约束条件和权衡过程全压进一个最高级形容词里。读者得到的是气势，不是推理。

“稳稳地接住你”是一种 warmth 模板。它把陪伴感、安抚感、响应感打包成一句情绪动作。放在真正的心理支持场景里未必完全不可用；放在技术协作或普通写作里，就会显得误诊。

“压实”“收口”“钉死”“兜底”是一种 agentic execution 模板，把任务推进包装成项目管理动作。

还有一种更完整的复合样本：

你准备用哪把刀？ A. 只用候选1（稳，不冒险） B. 候选1+候选2（硬度够，完全不伤模板） C. 三把都用，候选3配上解法句（最硬，但需要你在……） D. 你自己有另一把刀想放（说来听听）

这段话把多种口癖叠在了一起：A/B/C/D 是产品化的选择菜单；“哪把刀”“三把都用”把方案选择说成武器选择；“稳”“硬度够”“最硬”用强度词替代风险分析；“完全不伤模板”把模板当成会被刀伤到的物体；“说来听听”则是对话留钩子。它不是单个词别扭，而是一整套协作姿态被模板化：模型给用户一个像在决策、其实信息密度很低的菜单。

这些模板的共同点不是“错”，而是“省”。省 token，省结构搜索，省语气选择，省解释成本，也省 reward model 判断成本。短期看，它们很容易获得“清楚、直接、能干”的评分；长期看，它们会把语言压成一组高频宏。

四、错误的 credit assignment 会把能力和口癖一起奖励

“哥布林”案例之所以重要，不是因为这个词本身好笑，而是因为它给了一个近乎官方的口癖形成样本。

OpenAI 在 2026 年 4 月的《Where the goblins came from》里复盘过这件事：从 GPT-5.1 开始，模型越来越爱在比喻里提到 goblins、gremlins 等 creature metaphors；GPT-5.1 发布后，ChatGPT 里 goblin 使用率上升 175%，gremlin 上升 52%[11]。后续分析发现，这种语言高度集中在 Nerdy personality：Nerdy 只占 ChatGPT responses 的 2.5%，却贡献了 66.7% 的 goblin mentions[12]。

更关键的是 reward 侧的证据。OpenAI 发现，原本用于鼓励 Nerdy personality 的 reward signal 对含有 goblin 或 gremlin 的输出更友好；在审计的数据集里，这个 reward 对 creature-word outputs 的 positive uplift 达到 76.2%[12]。然后问题发生了迁移：奖励只施加在 Nerdy 条件下，但强化学习并不保证学到的风格只留在原条件里；如果后续 rollout 又进入 SFT 或 preference data，表层词癖就会被进一步强化，形成反馈环[13]。

这就是 credit assignment（信用分配/归因分配）的核心问题。

训练本来想奖励的是“playful、nerdy、有趣、能解释复杂问题”。但实际被一起奖励的，可能是某些恰好经常和高分回答共现的词。模型没有一个干净的因果标签告诉它：得分高是因为解释结构好，不是因为用了 goblin；得分高是因为语气合适，不是因为用了某个固定隐喻；得分高是因为行动有效，不是因为句尾很会说漂亮话。

对应到中文，机制并不难类比。

本来应该学到的能力 可能顺手学到的口癖 先给关键判断 每次都说“先说结论” 区分两个相近概念 凡事都写成“不是 X，而是 Y” 给出低风险方案 直接说“最稳” 展示可选方案 用 A/B/C/D 菜单替代真实权衡 表达方案强弱 用“刀”“硬度”“最硬”替代比较标准 对用户情绪有基本感知 动不动“稳稳地接住” 把 agent 任务推进到底 满篇“压实、收口、兜底、闭环”

从计算角度看，语言模型是在 token 序列上接受训练信号。偏好数据、reward model、SFT 数据、产品默认提示和用户反馈共同塑造的是输出分布，不是一个纯净的“好文风灵魂”。当某些短语长期与高评分输出共现，它们就会获得统计优势。再叠加低 verbosity，它们会变得更强，因为模板短语可以用很少 token 传递一个看似完整的姿态：模型懂、模型稳、模型会干、模型还很温暖。

这解释了为什么这些口癖会显得既有用又烦人。它们常常是有用行为的影子，而不是纯粹无用的噪音。最麻烦的也正是这一点：不能简单把影子删掉，因为影子后面确实连着一些需要保留的能力。

五、agentic post-training 里，行胜于言比漂亮话重要得多

对 agentic post-training 来说，一个基本判断很朴素：稳稳地解决问题，比偶尔来一句“稳稳地接住你”重要得多。

真正有价值的 agentic 能力，不是把执行感写出来，而是把执行做出来：理解目标、拆分任务、调用工具、检查结果、控制副作用、处理失败、继续推进、给出可验证产物。GPT-5 prompting guide 里关于 minimal reasoning 和 agentic workflow 的建议，本质上也是把模型往“别过早停下、持续更新、把任务完成”的方向推[14]。

在这个语境里，简洁是优点。对 coding agent 来说，最好的句子常常不是最漂亮的句子，而是最能降低用户监控成本、说明当前状态、指向下一步动作的句子。

但简洁不等于模板化。

高质量的简洁应该保留关键变量：看到了什么证据、做了什么假设、比较了哪些方案、为什么选这个路径、验证了什么结果。低质量的简洁则把这些变量压成几个口癖：“最稳”“先收口”“问题钉死”“一步到位”。前者减少噪音，后者减少信息。

这也是“AI 官话”真正烦人的地方：它把行动能力的外观误当成行动能力本身。agent 不需要反复宣称可靠；它需要用可复现步骤、可检查输出和可解释权衡证明可靠。

人狠话不多，行胜于言。对 agent 来说尤其如此。

六、该保留的词、该修的腔、该压的口癖

处理原则也应该分三层。

第一，专业术语不要误伤。fixture、wiring、preset、framing、落盘这类词，如果确实承担技术区分，就应该保留，最多补充中文解释。把所有不日常的词都删掉，只会让技术表达退化。

第二，翻译腔要翻回中文。clean 不一定都译成“干净”，sharp 不一定都译成“锋利”，catch 不一定都译成“接住”，nail down 不一定都译成“钉死”，heavy 不一定都译成“胖”。中文里本来有“清楚、准确、有力、收下、记下、确认、查明、敲定、占用大、状态重、成本高”这些更贴合语境的词。

第三，post-training 口癖要压频率，不是全封禁。偶尔说“先说结论”“不是 X，而是 Y”“最稳”没有问题；没有比较对象、约束说明和风险分析时，它们才是在替代思考。

关键不是反对某个词，而是要求模板补回信息：说“最小改动”，就说明小在哪里；说“兜底”，就说明兜的是什么失败模式；说“不是 X，而是 Y”，X 应该是真实可能的误解；想表达温暖，就先判断场景是否真的需要温暖。

七、机翻、化用、通感与新表达：边界不能一刀切

机翻腔的讨论还需要留一个口子：不是所有从英文来的表达都必然低级，也不是所有“不像传统中文”的说法都应该被改掉。语言一直在吸收外来结构。问题不在“是不是来自外语”，而在它有没有完成中文化：读者能不能直接读懂；它有没有带来新的表达能力；它是否比已有中文更准确；它是不是被作者有意识地调度，而不是模型无意识地直译。

“视觉记忆通常很胖”就是一个边界例子。如果它只是在把 heavy 硬译成胖，那它应该被改成“占显存大”“状态很重”“保留成本高”。但如果上下文已经明确在讨论一种像身体一样有体积、有惯性、有代谢成本的记忆结构，“胖”也可能成为一种通感式表达：把计算资源的沉重感转成视觉和身体经验。区别在于，前者只是直译，后者扩充了表达。

化用也是同理。金庸《笑傲江湖》的书名，常见说法认为来自《西游记》第九回渔夫词里的“得来烹煮味偏浓，笑傲江湖打哄”。[15] 在原语境里，这一句贴着渔夫的生活经验：捕到鱼，烹煮，味浓，在江湖上自得其乐；按一种很通俗的读法，“打哄”甚至可以被读成吃饱后的打嗝式满足。“笑傲江湖”在那里仍有很强的字面性。金庸把它拿来做武侠小说书名，就不是简单摘句，而是把渔樵闲适、江湖空间、自由人格、权力之外的精神姿态一起压进四个字里。它完成了意义迁移，也完成了新语境里的再创造。读者在这里能看到的，不是一个古词被搬运，而是一个字面场景被重新熔成了精神姿态。

所以，判断一句话是机翻腔、化用、通感，还是新表达，不能只看它能不能回译成英文。更好的标准有四条：是否提供新信息，是否可被上下文解释，是否比常规说法更准确，是否来自作者选择而不是模型惯性。如果“胖”只是 heavy 的替代，那它没有新信息；如果它让读者同时感到容量、惯性和维护成本，它就有表达增益。如果“桥成一个服务”换成“封装成服务”更准确，那“桥成”就是噪音；如果它真指两个协议、两个运行时或两个系统之间的适配层，bridge 这个隐喻就有保留价值。

这也是为什么 GPT 文风不能只靠“消灭 AI 味”来解决。消灭得太狠，会把新表达、新隐喻、新术语一起杀掉；放任不管，又会让英文骨架和训练口癖占领中文。真正需要的是更细的判断力。

八、结论：GPT 文风的问题，不是“黑话太多”这么简单

最终判断是：GPT 的黑话、口癖和文风问题，不能混成一团。专业术语承载协作精度，应该保留；机翻腔可理解但不自然，未必阻碍任务完成，却会腐蚀中文写作；post-training 口癖更深，模型被奖励简洁、温暖、清楚和能干活时，credit assignment 可能把这些目标和表层 token 绑在一起，生成一套高分回答的模板残留。

这并不否定 GPT 在 agent 场景里的价值。它越能干活，就越应该把“会干活”和“会说漂亮话”分开评价。稳稳地解决问题，比稳稳地接住用户重要。真正该警惕的不是某个词，而是模型把“高分回答的表情”误学成了“好表达本身”。
